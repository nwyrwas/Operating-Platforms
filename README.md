# 🎮 **Operating Platforms for The Gaming Room: Cross-Platform Web-Based Game Design**

Welcome to the **Operating-Platforms** repository! In this project, I developed the documentation and designed the architecture for expanding the existing Android game, **"Draw It or Lose It,"** into a **web-based platform**. The goal was to make the game compatible across multiple operating systems, including **macOS**, **Linux**, and **Windows**, while introducing several new features to enhance the gameplay experience.

## 📝 **Project Overview**

The client wanted to expand their Android game into a platform that supports **multiple players, multiple teams**, and a **single active instance in memory**. The main features include:
- **Cross-Platform Compatibility**: Ensuring the game works seamlessly on **macOS**, **Linux**, and **Windows**.
- **Multiplayer Support**: Facilitating games with multiple teams and players, each with unique game and team names.
- **Timed Rounds & Post-Time Guessing**: Implementing timed rounds, with players able to guess after time has expired.
- **Unique Identifiers**: Ensuring each game, team, and player has a unique identifier to maintain clarity and avoid conflicts.

### **Key Features**
- **Cross-Platform Design**: A web-based solution to run seamlessly across different operating systems.
- **Multiplayer Support**: Management of teams and players, including unique game, team, and player identifiers.
- **Game Mechanics**: Timed rounds with post-time guessing, creating a dynamic and engaging gameplay experience.
- **Domain Model**: Detailed documentation of the system architecture and design constraints.

### **Approach**
To ensure the design met the client’s needs, I focused on:
- **Cross-Platform Compatibility**: The primary goal was to create a web-based game that would run consistently on **macOS**, **Linux**, and **Windows**. I recommended using **web technologies** such as HTML5, CSS3, and JavaScript for front-end development, while leveraging **Node.js** or a similar back-end framework to handle multiplayer aspects.
- **User-Centered Design**: By understanding the client’s needs and end-user expectations, I ensured the design addressed features like **timed rounds** and **post-time guessing**.
- **Unique Identifiers**: A key challenge was ensuring each game, team, and player had a unique identifier to prevent any conflicts or confusion during gameplay.

## ⚙️ **System Architecture & Design Considerations**

### **Cross-Platform Compatibility**
The game’s architecture was designed to be accessible on multiple operating systems. By using a **web-based platform**, users can play the game on any modern browser, minimizing compatibility issues across different systems.

### **Game Features**
- **Multiplayer Functionality**: Multiple teams and players can join a game, with unique identifiers for each.
- **Timed Rounds**: Each round is timed, and players have the opportunity to guess even after time has expired.
- **Active Instance Management**: Only one active instance of the game is maintained at any given time, ensuring the game runs smoothly without conflicts.

### **Potential Future Enhancements**
- **Iterative Prototyping**: In future iterations, prototyping would be used to quickly build and test new features, gathering user feedback to refine gameplay mechanics.
- **User Testing**: Testing the web-based game with actual users to identify usability issues and improve the design.
- **Enhanced UI/UX**: Future revisions could include more detailed specifications for the user interface, with a focus on accessibility and ease of use.
